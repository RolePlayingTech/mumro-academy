3. Sprawdź samodzielnie

  1. Filtruj zaplanowane posty na LinkedIn (linkedin + scheduled): powinny pozostać DEMO-001 i DEMO-005 (szkic DEMO-003 jest wykluczony).
  2. Jeżeli eksperymentalne API document.modelContext jest dostępne, porównaj odpowiedź narzędzia get_publication_queue z filtrowaniem ręcznym.
  3. Kliknij Test odmowy: platform=instagram i zaobserwuj odrzucenie błędnego parametru przez walidator runtime bez zmiany stanu.
  4. Kliknij Test niezaufanej notatki DEMO-003 (DOM vs LLM): wywołuje on zarejestrowane narzędzie get_publication_queue({ platform: "linkedin", status: "draft" }), które posiada annotations.untrustedContentHint: true. Zauważ różnicę między ochroną DOM przed XSS (textContent) a ryzykiem pośredniego prompt injection dla modelu LLM.
  5. Odpowiedz, dlaczego readOnlyHint: true oraz untrustedContentHint: true są wskazówkami dla hosta, a nie zabezpieczeniem backendu.
Przykład wymaga eksperymentalnej obsługi WebMCP (np. Chrome z flagą chrome://flags/#enable-webmcp-testing) do natywnej rejestracji w document.modelContext. Interfejs człowieka działa w każdej przeglądarce.
